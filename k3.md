# WordWarp review — k3

A thorough pass over the codebase and the running app (source read + live probing + perf
measurements + screenshots). Findings are grouped by theme; each entry ends with a status
marker. `DONE` entries were implemented by me on a dedicated branch (see PR list at the
bottom). `OTHER-AGENT` marks areas where a concurrent agent already has an open branch; I
deliberately did not touch those files to avoid collisions.

Concurrent work detected on origin (do not duplicate):

- `fix/effect-paints` — paints (gradients/ramps) for strokes/glows/extrudes, AA strokes
- `fix/bevel-extrude` — real bevel profiles, extrude parameter wiring
- `chore/remove-dead-font-code` — deletes `src/text/harfbuzz.ts`, `src/text/font-metadata.ts`

## 1. Critical bugs

### 1.1 Workspace layout is broken: the artboard is pushed off-screen — DONE

`.workspace` defines only `grid-template-columns`; its single implicit row is `auto`, so it
sizes to the tallest panel's max-content. The preset panel (~30 cards, ~2900px) stretches the
row, `body { overflow: hidden }` clips the overflow, and `.canvas-viewport` ends up ~1750px
tall than the visible area (measured `clientHeight: 1747` on a 900px viewport). The artboard
is vertically centered in that oversized viewport, so on desktop it sits mostly below the
fold and on mobile the canvas appears clipped. Verified live: `.artboard-wrap` y=792 in a
viewport of 900.

Fix: constrain the row, e.g. `.workspace { grid-template-rows: minmax(0, 1fr); }`, letting
the side panels scroll internally.

### 1.2 Toasts never auto-dismiss — DONE

`ui-store.pushToast` appends with no timeout; success/error toasts stack up forever until
clicked. Add per-tone TTL (info/success ~4s, warning/error ~8s) with cleanup on dismiss.

### 1.3 Playing an un-animated document re-renders at full cost every frame — DONE

With zero enabled animation tracks, pressing Play still runs a rAF loop that calls
`evaluateDocumentAtTime`, which `structuredClone`s the whole document every frame and forces
a full canvas re-render (~150ms/frame measured) of an identical image.
Fix: `evaluateDocumentAtTime` returns the same document reference when no track is enabled;
additionally disable/hint the Play button when the document has no enabled tracks.

### 1.4 `removeSelected` can select the wrong element — DONE

`App.tsx`: if the selected id is stale (e.g. after undo removed it), `selectedIndex` is -1
and `document.elements[selectedIndex + 1]` silently selects element 0. Guard for -1.

## 2. General bugs

### 2.1 Texture overlay ignores `scale` and `rotation` — OTHER-ADJACENT (renderer file)

`renderTexture` (`cpu-effects.ts`) never reads `effect.scale`/`effect.rotation`; the
inspector's "Scale" slider for texture overlays is a no-op. (File is owned by other agents'
branches; flagging for them. If still open after those merge, fix in pattern sampling.)

### 2.2 SDF threshold at alpha ≥ 128 loses anti-aliasing — OTHER-AGENT

`signedDistanceField` binarises coverage, so strokes/bevels/glows get hard, jagged 1-bit
edges on curved glyphs. Partially addressed by `fix/effect-paints` (AA strokes).

### 2.3 Bevel implementation gaps — OTHER-AGENT

`pillow`/`strokeEmboss` styles collapse to the inner band, `technique` (smooth/chisel) and
`soften` are ignored, and `glossContour` is applied to both highlight and shadow. Addressed
by `fix/bevel-extrude`.

### 2.4 Extrude: only parallel mode, banded sides — OTHER-AGENT

`mode: 'perspective'`/`vanishingPoint`/`strength`/`autoShade`/`facePaint` are all ignored;
sides are built from ≤96 offset-alpha unions, which bands on curves and large depths.
Addressed by `fix/bevel-extrude`.

### 2.5 Fake canvas rulers

`.canvas-rulers` hardcodes 0/300/600/900/1200 across the top regardless of zoom, scroll, or
canvas size. Either remove them or generate ticks from the actual document canvas size and
zoom. Recommend removal (they imply precision the app doesn't have).

### 2.6 "Fit" zoom button doesn't fit — DONE

`setZoom(1)` labelled "Fit". It should compute zoom from viewport vs. artboard size. Also:
zoom is reset to 100% on every reload and there are no preset zoom levels.

### 2.7 Undo/redo unreachable on tablet/mobile

`.history-actions` is `display: none` below 1050px, so touch users have no undo at all.
Keep compact undo/redo buttons visible at all widths.

### 2.8 `autoFocus` on the content textarea — DONE

Steals focus on load (and pops the mobile keyboard on first open). Remove it; the field is
one tab-stop away.

### 2.9 GIF/APNG export of a static document produces N identical frames

With no enabled tracks, `documentAnimationDuration` returns 2s and the exporter renders
~24 identical frames (~2.4s of CPU). 1.3's fix makes this cheap to detect; warn the user or
short-circuit to a 1-frame animation.

### 2.10 Text rendering depends on locally installed fonts

Default doc uses "Arial Black", which doesn't exist on most Linux systems or Android; the
fallback metrics differ per machine, so share links and golden renders diverge across
platforms. Needs bundled/web fonts (the dead `harfbuzz.ts` pipeline was headed that way) or
at least `document.fonts.load` + a metrics-stable fallback strategy.

### 2.11 `preserveDrawingBuffer: false` makes the preview canvas unreadable

`drawImage`/readback of the WebGL canvas yields a blank image (verified). Fine today, but it
blocks future features (document thumbnails, preset live-previews, tests that assert on
pixels). Consider `preserveDrawingBuffer: true` — cost is negligible for one canvas.

### 2.12 Keyboard: `/` hint in the search box does nothing — DONE

The search field shows a `/` kbd hint, but no shortcut focuses it. Add `/` (focus search),
Escape (deselect/blur), arrow keys (nudge selected element), Ctrl/Cmd+D (duplicate layer).

### 2.13 No favicon — DONE

`index.html` has no `<link rel="icon">`; `public/wordwarp-icon.svg` exists but is never
linked. Browser tab shows the default icon.

## 3. Performance

Measured: **~150–195ms per keystroke re-render** on the default chrome stack (≈5–6fps while
typing) at 1200×630. Everything below stems from "recompute the world on every edit, on the
main thread, with no caching".

### 3.1 No render caching/invalidation

Every store update re-runs: text layout, face rasterisation, full EDT-based SDF, all blurs,
the ≤96-pass extrude union, post effects. The PLAN (§6.4) calls for content-addressed stage
caching; dragging a drop-shadow slider should not reshape text. Big wins available:

- Cache the SDF per face-alpha content (it's the single largest cost; blurs second).
- Cache `layoutText` per (text, font, layout) tuple.
- Skip `renderEffectStack` entirely when no effect is enabled (already done) and reuse
  per-effect layers when only a later slot changes.

(Renderer files are other agents' turf; noted for them.)

### 3.2 Warped text draws 576 clipped triangles per element per frame

`drawWarpedSurface` uses a fixed 24×12 grid → 576 `save/clip/transform/drawImage/restore`
calls. Grid density should adapt to warp curvature; straight warps (slants, fades) can use
2×1.

### 3.3 `applyPostEffect` always does 2 full-buffer copies + a mix pass

`image.data.slice()` ×2 plus a final blend loop, even when the effect is a no-op at
`opacity: 0`. Early-out when `amount`/`opacity` are zero (opacity is checked upstream, but
grain/scanline amounts aren't).

### 3.4 `evaluateDocumentAtTime` structured-clones per frame — covered by 1.3.

### 3.5 Preview render scheduled via nested rAF with `useDeferredValue`

Works, but during a drag-move the transaction updates the store 60×/s → 60 full renders/s.
Throttling preview renders to the display's next frame when updates arrive faster would
help; the deferred value mostly covers it. Low priority.

### 3.6 `blurAlpha` is O(n·radius) Float32 work with no downscale for large σ

PLAN says downsample 4× for σ > 32; not implemented (renderer file — other agents).

## 4. Missing features (by user impact)

1. **No color editing anywhere.** You cannot change a fill color, stroke color, glow color,
   or gradient stop without applying a preset. Solid paints need at minimum a color input;
   gradients need stop editing eventually. **DONE (solid paints).**
2. **No export options UI beyond format.** Resolution (fixed 2×) — being fixed by another
   agent. Also missing: padding/autoFit controls, background toggle, JPEG/WebP export.
3. **No font management.** 7-entry datalist of system fonts; no Google Fonts, no upload, no
   style/axis controls despite `FontSpec` supporting them.
4. **Warp UI is preset+bend+one slider.** `adj[1]`, `distortH/V`, `keepUpright`, and the
   mesh/path/perspective warps (all implemented in the engine!) have no UI. The "Warp"
   toolbar button is disabled.
5. **Effect editing is one slider per effect.** No angle, opacity, blend mode, color,
   distance, spread, or contour editing. The stack is reorderable only via UP/DN buttons
   (the drag grip is decorative).
6. **No layer operations.** No duplicate, rename, hide, lock, opacity, or blend-mode UI
   (model supports all). **Partially DONE (duplicate via Ctrl+D, visibility toggle).**
7. **No canvas size/background UI.** CanvasSpec fields exist; only the 1200×630 default is
   reachable.
8. **No document management.** One autosaved document only; no New/Open/Duplicate, no
   `.ww` file import/export (share URLs exist), no named documents list (the DB has a
   `by-modified` index ready for it).
9. **No animation UI.** Tracks exist only via presets; you can't add/remove/tune tracks,
   and the inspector never shows `element.animations`.
10. **No shape/image elements** despite the model supporting them.
11. **No user presets** (save/fork/share stacks) — PLAN's "presets are data" promise.
12. **No multi-select, alignment, or distribution** of elements.
13. **JPEG export / copy-to-clipboard** — cooltext.com's export honesty is the bar; copying
    a PNG to the clipboard is a one-liner with `navigator.clipboard.write`.

## 5. Visual issues & layout

1. Workspace row bug (1.1) — the big one.
2. The artboard has `overflow: hidden`, so effects extending past the canvas edge are
   invisibly clipped in preview; fine, but the selection overlay (`overflow: visible`)
   draws outside while the artboard clips — mildly confusing.
3. Renderer badge ("WEBGL2") implies GPU rendering; the GPU path is only a fullscreen blit
   of the CPU-rendered canvas. Consider renaming the badge to reflect reality (or drop it).
4. Effect chips are decorative gradients unrelated to the effect type; the `effect-{kind}`
   class hook exists but no per-kind styling is defined.
5. Preset cards render a fake "Ww" over the palette gradient — they don't preview the
   actual style (a `Chrome Classic` card and a `Gunmetal` card differ only in gradient).
   Rendering true thumbnails with the real renderer would be a big credibility win (needs
   2.11 fixed first).
6. On narrow widths the topbar crowds: Share + PNG + Export + panel toggles overflow at
   ~360px (mobile CSS handles ≤740, but 741–1050 with panels open can squeeze).
7. The selection overlay stroke is `vector-effect: non-scaling-stroke` — good — but the
   dashed rect has no drag handles; users will expect corner handles.
8. Disabled "Warp" toolbar button ships in the UI; hide unimplemented tools rather than
   tease them, or implement the mesh-warp overlay (engine is ready).
9. `.canvas-status` ("1200 x 630 / TRANSPARENT") is static text; it doesn't reflect export
   bounds or the autoFit result.

## 7. Novel / delightful / quirky ideas

1. **Warp-handle overlay.** The mesh warp engine is complete — add a 4×3 draggable grid on
   the canvas when the Warp tool is active. Instant "wow" differentiator; nothing else on
   the web has it.
2. **Live preset thumbnails** (see 5.5): render "Aa" with each preset's actual stack into
   tiny offscreen canvases once at startup (30 presets × ~80×55px ≈ trivial). Turns the
   library into the product's best salesperson.
3. **"Remix" dice button** — randomize seeded params (post seeds, gradient hue rotation,
   warp adj) with a seeded RNG; shift-click to lock aspects. Shareable by URL for free.
4. **Time scrubber** next to Play: a slider over t∈[0,1) for picking the perfect animation
   frame before export (also enables "export frame as PNG").
5. **One-click "WordArt 97 tribute mode"**: toggle that forces the classic Office ramps +
   textSlantUp + extrude defaults on new text. Nostalgia bait, near-zero cost.
6. **Global-light drag widget**: a tiny sun-dial in the inspector; dragging rotates
   `globalLight.angle` live (it already drives bevel + shadows together).
7. **APNG/GIF "ping-pong" export flag** for smoother loops of non-looping tracks.
8. **Share-card mode**: `?embed=1` renders the document full-bleed without chrome, for
   embedding in Notion/obsidian pages.
9. **Deterministic meme templates**: a handful of canned multi-layer compositions
   ("Impact top/bottom text", "VHS title card") as loadable documents.
10. **Easter egg**: typing "CLIPPIT" anywhere swaps the font picker icon for Clippy.

## 8. New style ideas (preset-library additions) — DONE (subset)

Candidates that the current engine can already express (verified against implemented
effects):

1. **Vaporwave Mall** — pink/cyan split gradient, scanlines, slight aberration, arch warp.
2. **Acid Chrome** — chrome-ii ramp, heavy aberration + glitch, inflate warp.
3. **Sticker Bomb** — thick white outside stroke + hard offset shadow (spread 100%, size 0)
   on flat fill.
4. **Caution Tape** — yellow/black gradient at 45°, chisel bevel, wave warp.
5. **Deep Fried** — oversaturated gradient + grain + halftone post, for the meme audience.
6. **Blueprint** — dark blue fill, white 1px stroke, scanlines, no shadow.
7. **VHS Title Card** — white fill, huge cyan/magenta double drop shadows (RGB-split look
   without the post effect), slight slant.
8. **Jelly** — translucent fill (alpha < 1), big inner glow white, pillow bevel, inflate.
9. **Rusty Sign** — brown/orange ramp, noise texture overlay, inner shadow, deflate.
10. **Arcade Cabinet** — neon double-stroke (magenta outer, white inner), glow, wave warp.

Engine gaps for future styles: contour editor, per-effect blend UI, gradient-stop editor
(unlocks true "fire"/"ice" styles), matcap library (only one generic matcap exists),
stroke dashes (ignored by renderer), and text-on-path warp UI.
